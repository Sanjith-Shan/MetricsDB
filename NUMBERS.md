# NUMBERS

Every figure MetricsDB reports, generated by `bench/ledger.py` from `results/*.jsonl`. Each section names the file its rows come from. Where an experiment was repeated, cells show the median with the range in brackets.

**Machine.** One mini PC: AMD Ryzen 3 4300U (4 cores), 16 GB, Windows 11 with WSL2 (Ubuntu 24.04, 2 vCPU and 6 GB given to the VM). The database under test, the load generator and the query client all run inside that VM. VictoriaMetrics and InfluxDB run in Docker in the same VM with their default settings, one database at a time. The box is shared with other jobs, so each row records the host CPU and WSL load next to it. **Data:** the standard benchmark (TSBS) DevOps use case, 100 hosts, 24 hours at 10-second intervals: 7,776,000 lines, 87,264,000 samples. Generated by the benchmark, not production traffic.

## exp5: a storage node killed mid-write (`results/exp5.jsonl`, timeline in `results/exp5_timeline.jsonl`)

3 storage nodes and a router, each its own JVM. 1,000 series, one sample each every 100 ms of wall time (10,000 samples/s offered) through the router. Node n1 gets SIGKILL at 20 s and is restarted at 40 s; the run ends at 60 s. A client that gets an error keeps the batch and retries it, as Prometheus would. A probe query every 250 ms counts the series it can see. Afterwards hints drain, anti-entropy runs twice, and every acknowledged sample is checked bit for bit through the router and on each of its replicas.

## Fault injection (`results/faults.jsonl`)

3 storage nodes at RF=2 under a steady write load; a nemesis, one node at a time, kills a node with SIGKILL and restarts it, freezes it with SIGSTOP, or drops its link to the router (a TCP proxy that resets the connection), each for 1.5 to 5.5 s. Then all faults heal, hints drain, anti-entropy runs, and the checker reads every acknowledged sample through the router and on both replicas.
